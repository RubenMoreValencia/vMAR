# G0.5-E.5.4.2 — Bounded transfer, robustness and contribution audit

**Goal:** decide whether the existing adaptive coupling hypothesis merits
retention as an experimental extension. This is a deliberately **bounded**
research gate, not another expansion of the core API.

## Controlled scientific comparison

The same dataset, targets, numerical field, initial weights and gradient
evaluation budget are used across three activation families:

- `tanh` — smooth, nonparametric, 3 neural state coordinates.
- `prelu` — piecewise-smooth, trainable negative slope, 4 coordinates.
- `swish` — smooth, trainable beta, 4 coordinates.

Each is evaluated with Euler/RK4, first-weight perturbations `-0.1,+0.1`,
initial memory values `-0.8,+0.8`, and policies:

1. `observe` (`c=0`);
2. `fixed` (`c=0.2`);
3. `adaptive` (bounded coupling from gradient-memory alignment).

There are **72 trajectories** and **24 paired contrasts** between adaptive
and the two baselines, plus **24 independent R–C23 parity cases** for the
adaptive paths.

## Budget and estimands

All trajectories use the same final horizon `t=1`. All policies pay for
one diagnostic gradient per step, including baselines. Euler uses 20 steps
(`20 field + 20 diagnostic` = 40 gradient evaluations), RK4 8 steps
(`32 field + 8 diagnostic` = 40). Loss reporting and non-gradient runtime
costs are outside this narrowly defined budget.

Report paired final-loss differences for the SAME model, method, weight
perturbation and memory initialization:

```
delta_obs   = loss_adaptive - loss_observe
delta_fixed = loss_adaptive - loss_fixed
```

Negative values favor adaptive in this fixture; positive values do not.
Ties within numerical tolerance must be reported as ties. Aggregate means
alone cannot establish transfer. No inferential independence is assumed:
Euler and RK4 reuse the same small dataset and initial factors.

## Reproduction

1. Use the already validated R package `vMAR.Core 0.0.12` and C23 library
   `vMAR 0.1.10-alpha`.
2. Run `source("reference/run_R_transfer_audit.R")` from the C project root
   after `devtools::load_all()` in R.
3. The script writes:
   - `reference/e542/transfer_results.csv` (72 cases),
   - `reference/e542/paired_differences.csv` (24 pairs),
   - `reference/vmar_transfer_parity.csv` (24 adaptive cases).
4. Reconfigure and build CMake, run all CTest suites, and execute
   `vmar_test_transfer_parity reference/vmar_transfer_parity.csv`.

The extra C23 invariant suite checks that absence/opposition/alignment are
handled correctly for all three activation families. No core behavior changes.

## Stopping and decision criteria

Close this hito after the 72/24/24 audit, without open-ended parameter
search. Record each activation family as favorable, unfavorable, or
inconclusive relative to the two baselines and publish the pairwise values.
Retain the adaptive rule as an *experimental option* unless repeated
evidence beyond one dataset supports stronger inclusion.

Adam is **not** used as a numerical comparator in this hito: its discrete
update count, gradient evaluation accounting, initialization, and tuning
would require a separate, pre-registered fair comparison. RK4 is a numerical
integrator, not an optimization competitor or exact solution. This benchmark
does not establish a universal learning law or out-of-sample generalization.
