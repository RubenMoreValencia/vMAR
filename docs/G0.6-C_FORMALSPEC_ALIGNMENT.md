## 2. Contract vocabulary

Each C operation is described by:

| Field | Meaning |
| --- | --- |
| `PRE` | Required domain, dimension, finite values, buffers and aliasing |
| `INV` | Invariant preserved across a valid call or accepted transition |
| `POST_OK` | Defined output on `VMAR_OK` |
| `POST_ERR` | Defined rollback or explicitly unspecified outputs on failure |
| `REF` | Original R analogue/equation and fixture requirements |
| `TEST` | Deterministic executable contract; limitations of coverage |

Quantification convention: `∀i∈[0,d)` covers every buffer coordinate.
`finite(x)` means each element is finite, `disjoint(A,B)` refers to the
documented buffer domains, and `unchanged(x)` means exact equality to the
precall content (including time and step counter where specified).

## 3. Normative core contracts

### FS-C01 — Workspace sizing

`vmar_workspace_required(method,d,out)`

- `PRE`: `d>0`, `out!=NULL`, `method∈{EULER,RK4}`, multiplication capacity
  fits `size_t` and `sizeof(double)`.
- `POST_OK`: `*out = d` (Euler) or `5d` (RK4), with no input mutation.
- `POST_ERR`: status `VMAR_ERR_ARGUMENT` or `VMAR_ERR_DIMENSION`.
- `TEST`: `vmar_core_contracts`, `vmar_formal_contract_alignment`.

### FS-C02 — Integrator transition

`vmar_step(method,t,h,f,ctx,s,d,w,wlen,s_next)`

- `PRE`: valid method and workspace; `h>0`; finite `t,h,s`; `f` valid;
  buffer nonoverlap rules from `vmar.h` honored.
- `INV`: caller's confirmed `s` is preserved when output is disjoint; an
  error never modifies `s_next`; all successful output coordinates are finite.
- `POST_OK`: Euler `s_next = s+h f(t,s)` or classical RK4 stages, evaluated
  at declared times, with exactly 1 or 4 callback calls respectively.
- `POST_ERR`: `s_next` is unchanged; field callback failure maps to
  `VMAR_ERR_FIELD`; nonfinite stages/results to `VMAR_ERR_NUMERIC`.
- **Limitation:** absence of numerical error on one step is not a proof of
  global stability, convergence or positivity preservation for all fields.
- `TEST`: `vmar_core_contracts`, R parity, `vmar_formal_contract_alignment`.

### FS-C03 — Canonical state layout

`vmar_state_layout_make(d,kind,layout)` /
`vmar_state_layout_validate(layout,s,n)`

- `PRE`: `d>0`, kind in {parameters, first-memory, second-moment}; no
  multiplication overflow; correct caller-owned buffer capacity.
- `INV`: contiguous and disjoint fixed-length blocks (`theta`, optionally
  `m`, optionally `v`), each with `d` entries; no hidden allocation.
- `POST_OK`: `n=kind*d` and canonical offsets; all entries finite; when `v`
  exists, `∀i v_i>=0`.
- `POST_ERR`: input layout and state unchanged.
- `TEST`: `vmar_state_layout_contracts`,
  `vmar_formal_contract_alignment`.
- **Limitation:** structural ability to hold `v` is not a scientific
  promotion of M2 or M2C.

### FS-C04 — Neural gradient and field

- `PRE`: finite row-major data, targets, parameters, valid dimensions;
  activation and derivative callbacks satisfy their contracts.
- `INV`: supervised MSE `L(theta)>=0`; gradient dimension equals theta;
  learning field uses the same gradient independently of Euler/RK4.
- `POST_OK`: finite loss and analytic gradient, field `theta'=-eta*grad L`
  for the uncoupled baseline.
- `POST_ERR`: output behavior follows the documented function-specific
  contract; **do not assert universal rollback** (neuron APIs explicitly
  allow unspecified outputs on failure).
- `TEST`: `vmar_neuron_contracts`, `vmar_custom_activation_contracts`,
  source and R-C23 parity fixtures.

### FS-C05 — Memory relaxation

- `PRE`: finite equal-sized memory and observation, positive `h,tau`.
- `POST_OK`: for constant input `g` over `[t,t+h]`,
  `m_next = m + (1-exp(-h/tau))*(g-m)` (implemented stably via `expm1`).
- `INV`: no mutation of caller's input memory and signal buffers under
  documented nonoverlap conditions.
- `TEST`: `vmar_memory_contracts`,
  `vmar_formal_contract_alignment`, R reference fixtures.
- **Limitation:** frozen-input exactness is not exactness for varying gradients.

### FS-C06 — Transactional control

- `PRE`: complete and valid policy; positive step, reduction in `(0,1)`,
  bounded attempts, adequate workspace, finite confirmed state/time.
- `INV`: rejected proposals do not change confirmed state, time, or step ID;
  retries start from the same confirmed state.
- `POST_OK` on acceptance: candidate meeting declared loss criterion is
  committed; time and step ID updated once; attempts and field costs reported.
- `POST_OK` on exhausted retries: rejected report with original confirmed
  state/time/ID preserved.
- `POST_ERR`: only guarantees explicitly documented by each controller may
  be assumed; reports on errors are unspecified.
- `TEST`: `vmar_control_contracts`, `vmar_adaptive_control_contracts`,
  regime/intervention/robustness tests and parity fixtures.
- **Limitation:** a successful local loss gate does not prove global
  improvement, generalization or a Lyapunov theorem.

### FS-C07 — Observer / controller separation

- `PRE`: valid confirmed state and explicit diagnostic thresholds.
- `INV`: diagnostics describe the current trajectory; they do not alter
  it unless an explicitly selected policy is subsequently invoked.
- `POST_OK`: recorded alignment, memory and gradient magnitudes are finite
  and describe the stated sample/configuration.
- `TEST`: regime/transfer/intervention contracts and reported R-C23 parity.
- **Limitation:** descriptive regime labels are not theorem-certified
  stability classes.

### FS-C08 — Experimental boundaries

- Adam discrete optimizer and second-moment differential comparators stay
  under `reference/`, outside the installable `vmar_core` target.
- The documented 12/12 worse M2C comparisons reject that **specific**
  intervention for core promotion, not all possible second-moment policies.
- An extension must separately provide mathematics, ownership, domain,
  test fixture, quantitative acceptance and a promotion decision.

expected error behavior, executable test and what remains unproven. This
enables a later function-by-function reconciliation against actual FormalSpec

## 5. Executable audit introduced in this stage

`tests/test_formal_contracts.c` exercises the following non-exhaustive
properties on both Euler/RK4:

1. Declared workspace requirement and field-evaluation count.
2. Preservation of confirmed input state.
3. Rollback when field rejects, produces nonfinite output, step is invalid,
   or workspace is undersized.
4. Linear field scale/sign consistency in a controlled example.
5. Canonical `[theta,m,v]` layout, valid domain and dimensional rejection.
6. Frozen-input exact exponential relaxation with immutable inputs.

**Local isolated GCC C23 run:** 38 assertions, 0 failures. This test is named
`vmar_formal_contract_alignment` in CTest. It adds one suite to the *actual*
Mac fixture-dependent test count. The earlier user report contained 17 suites
(not the initially forecast 18); investigate optional fixture presence before
comparing raw suite totals.
