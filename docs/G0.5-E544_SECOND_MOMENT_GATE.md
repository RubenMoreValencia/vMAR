# G0.5-E.5.4.4 — Second-moment memory: scientific value gate

Status: **reference implementation ready; R/C23 experimental parity and
architectural decision pending empirical results**.

## Research question

Does a nonnegative differential second-moment state provide useful observation
or justified feedback control beyond the established first-moment memory?
The goal is not to reproduce Adam, but to assess observability, mathematical
consistency and attributable learning effects within vMAR's philosophy.

## Exact experimental definitions

Let `theta` be all trainable neuron parameters, `g=grad(L(theta))`, and `m`
the existing vMAR memory. Three **preregistered** variants are tested:

| Mode | State | Parameter dynamics | Moment dynamics |
| --- | --- | --- | --- |
| M1 | `[theta,m]` | `theta'=-eta*(g+0.2*m)` | `m'=(g-m)/0.8` |
| M2 | `[theta,m,v]` | **identical to M1** | additionally `v'=(g^2-v)/0.4` |
| M2C | `[theta,m,v]` | `theta'=-eta*(g+c_eff*m)` | same two memories |

For M2C, `c_eff=0.2/(1+sqrt(mean(v))/0.1)`. This monotone,
nonnegative attenuation is an explicit, **unvalidated intervention hypothesis**,
not a derived Adam rule or an optimum policy. `v` starts at zero and is
nonnegative in the continuous relaxation with nonnegative forcing. Numerical
stages outside the allowed domain are rejected; integrator step selection must
respect that domain. No bias correction, Adam update, gradient clipping or
parameterwise preconditioning is used.

## Bounded experiment

- Same 3-sample neuron dataset and analytic full-batch gradient as E.5.4.3.
- Three activations: `tanh`, trainable `prelu`, trainable `swish`.
- Two theta perturbations: `-0.1` and `+0.1`.
- Euler 40 steps or RK4 10 steps over the same time interval `[0,1]`.
- **40 field gradient evaluations** and shared final integration time in all
  variants; initial and final diagnostic loss evaluations are not counted.
- `m0=0`, `v0=0` for all applicable modes, same initial `theta`.
- 3 models x 2 perturbations x 2 integrators x 3 modes = **36** runs.
- 12 paired configurations; 12 M2C R–C23 parity fixtures.

This design compares equal time and gradient count; it does **not** assert
equal wall-clock work or memory footprint. RK4 uses fewer, more expensive
steps. The M2 state has greater memory and arithmetic cost than M1.

## Acceptance and identifiability criteria

1. **Null intervention:** the M1 and M2 parameter and first-memory trajectories
   must coincide to numerical tolerance (`1e-12` for their final losses).
   Without this, a claim about second-moment control is confounded.
2. **Integrity:** finite trajectories; nonnegative second moment; valid
   dimensions and relaxation constants; zero-initialized memories.
3. **Attribution:** paired `M2C - M2` loss differences, with initial theta,
   data, time, gradient budget and integrator held equal.
4. **Parity:** 12 R-C23 cases agree on final theta, both memories, loss,
   numerical time and gradient accounting.
5. **Restraint:** no general superiority claim from this small single dataset.

If M2 provides valid observation but M2C lacks demonstrable and transferable
benefit, retain observation as an opt-in extension only. If the independent
second moment does not improve interpretation or observability in new scenarios,
do not promote it to the stable core. Any control promotion needs predeclared
acceptance thresholds, broader scenarios and cost/benefit evidence.

## Selection of other Adam-derived mechanisms

| Mechanism | Current decision | Evidence needed before promotion |
| --- | --- | --- |
| Second-moment relaxation | **Research-only** | This gate, perturbation transfer, nonnegative domain |
| Bias correction | **Deferred** | Show an initialization bias relevant to vMAR state/time |
| Per-coordinate preconditioner | **Deferred** | Stable scaling, unit invariance, interpretability, robust advantage |
| Hyperparameter adaptation | **Already explored independently** | Transfer advantage and transparent state contracts |
| Full Adam within core | **Not proposed** | No distinct justification under vMAR philosophy |

## Reproduction

Load the installed/development `vMAR.Core` package first. From the C project
root run in R:

```r
source("reference/run_R_second_moment_audit.R")
```

The script creates:

- `reference/e544/second_moment_results.csv` (36 rows)
- `reference/e544/paired_contrasts.csv` (12 rows)
- `reference/vmar_second_moment_parity.csv` (12 rows)

Then rebuild with CMake and execute CTest and:

```sh
./cmake-build-debug/vmar_test_second_moment_parity \
  reference/vmar_second_moment_parity.csv
```

The second-moment C implementation and header remain under `reference/`,
outside the installed `vmar_core` and its public ABI. These are scientific
experimental comparators, not a committed architecture migration.
