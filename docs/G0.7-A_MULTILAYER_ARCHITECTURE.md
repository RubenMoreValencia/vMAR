# G0.7-A — Arquitectura matemática de redes neuronales multicapa extensibles

**Status:** mathematical architecture and experimental R reference vMAR.Core
0.0.13 prepared. **R unit tests, documentation and `R CMD check` remain
pending on the researcher's Mac.** C23 API described here is **provisional**:
the current installable C23 core stays at vMAR 0.1.12-alpha, with no new MLP
symbols or ABI break.

## 1. Source reconciliation

- `DSNeuralRNAS/R/mlp.R` exports `rnas_init_mlp`,
  `rnas_validar_params_mlp`, `rnas_mlp_forward`, `rnas_mlp_loss`,
  `rnas_mlp_backward`, `rnas_update_params_mlp`, `rnas_train_mlp`,
  `rnas_predict_mlp`: one hidden layer, matrices `W,b1,v,b2`, MSE and
  ordinary backpropagation. Initial parameters can use a seed.
- `vMAR.Core/R/mlp.R` exposes `vmar_mlp_forward` and
  `vmar_mlp_loss_gradient`: one hidden layer with `w1,b1,w2,b2`, a common
  catalog of activation functions, analytic MSE gradient.
- `DSNeuralRNAS.MLP/R/02_core_mlp_rnas.R` provides integration, training,
  decision and application workflows, not a second canonical network
  mathematics suitable for direct copying into C23.
- `ML.DSNeuralRNAS` studies policies, regimes and intervention semantics;
  it contributes audit hypotheses, not extra mandatory optimizers.

**Decision:** maintain existing one-hidden-layer functions as source
compatibility references. The new mathematical architecture is an *arbitrary
depth* feedforward network. It must degenerate exactly to the old MLP when
given widths `(d,h,1)` and activations `(phi,identity)`.

## 2. Mathematical model and invariants

Let `L >= 1` be the number of affine layers and let
`d_0,d_1,...,d_L` be positive integer widths. G0.7-A uses `d_L=1`
for scalar regression, with multiple-output models reserved for later audit.
For a batch `X` in `R^(n×d_0)` and layer `l=1..L`:

```
Z_l = A_(l-1) W_l^T + 1_n b_l^T
A_l = phi_l(Z_l)
A_0 = X
W_l in R^(d_l × d_(l-1)), b_l in R^(d_l)
```

Each `phi_l` may differ. Built-in activation value and input derivative are
obtained from `vmar_activation_eval`. The complete reference activation list
is `tanh, sigmoid, identity, softplus, relu, leaky_relu`.

Scalar-output objective:

```
L(theta) = (1/n) Σ_i (A_L[i,1] - target[i])²
```

With `D_L = (2/n) (A_L - y) ⊙ phi'_L(Z_L)`, descending recursion gives:

```
grad_W_l = D_l^T A_(l-1)
grad_b_l = column_sums(D_l)
D_(l-1) = (D_l W_l) ⊙ phi'_(l-1)(Z_(l-1))
```

This is a mathematical identity under differentiability, and an explicit
subgradient convention at piecewise activation kinks. These derivatives do
not establish a convergence theorem or universal prediction quality.

## 3. Canonical packed state (one source of truth)

At each layer, concatenate **row-major** entries of `W_l`, then `b_l`;
concatenate layers in forward order. The parameter dimension is:

```
p = Σ_(l=1)^L d_l (d_(l-1) + 1)
theta = [row_major(W_1), b_1, ..., row_major(W_L), b_L]
```

The same order must hold for `grad_theta`, `m` and, optionally, `v`.
`vmar_network_spec()` rejects invalid dimensions and overlarge parameter
counts; `vmar_network_pack()/unpack()` implement the bijection. All arrays
are explicit and finite. In C23, offsets must be calculated without integer
overflow and remain stable for a versioned descriptor.

## 4. Dynamical-systems interpretation

Let `theta(t)` be the trainable network state; its baseline learning field is:

```
theta'(t) = -eta * grad_theta L(theta(t); X, y)
```

`eta` is a positive field scale, distinct from numerical integration step
`h`. Euler or RK4 integrates **the same field**; their numerical trajectories
may differ. The new R function `vmar_network_gradient_field` supplies this
field without choosing either method.

First-moment memory remains an independent state block:

```
s(t) = [theta(t), m(t)]
m'(t) = (grad L(theta(t)) - m(t)) / tau
```

Possible feedback `theta'=-eta [grad L + c·m]` must be **explicit opt-in**.
The formula is a research candidate, not a mandatory neural learning rule.
The same accepted/rejected transactional principle and external trace
recording apply at any parameter dimension.

## 5. Trainable activation parameters: architectural extension point

For `phi_l(z;alpha_l)` with trainable `alpha_l`, a future stable layout
appends a declared `alpha_l` block after that layer's biases, and the
gradient requires the parameter Jacobian `∂phi_l/∂alpha_l`. Fixed custom
activations need only `phi` and `∂phi/∂z`.

**Not implemented in the first generalized MLP reference.** This boundary
avoids claiming support merely because the one-neuron custom activation
module supports trainable PReLU/Swish parameters. Its generalization to
multiple layers requires a separate finite-difference and state-layout gate.

## 6. R reference API delivered

| Function | Contract |
| --- | --- |
| `vmar_network_spec(widths,activations)` | Declarative arbitrary-depth shape and offsets, scalar output |
| `vmar_network_pack(spec,weights,biases)` | Canonical parameter vector, finite/shape checked |
| `vmar_network_unpack(spec,theta)` | Inverse mapping to matrices and biases |
| `vmar_network_forward(x,spec,theta)` | Full-batch scalar predictions |
| `vmar_network_loss_gradient(x,target,spec,theta)` | MSE, output predictions, analytic packed/structured gradients |
| `vmar_network_gradient_field(x,target,spec,eta)` | Differential field; integrator independent |

There is no automatic random initialization, implicit update loop, hidden
optimizer selection, graphical interface, or untested default adaptive
activation. Existing `vmar_mlp_*` remains backward compatible.

## 7. Provisional C23 API boundary (not installed)

The next implementation hito may expose a versioned descriptor resembling:

```
vmar_network_layout_create(widths, count, activation_specs, out_layout);
vmar_network_forward(layout, dataset, theta, workspace, predictions);
vmar_network_loss_gradient(layout, dataset, target, theta,
                           workspace, loss, gradient);
vmar_network_field(time, theta, dimension, derivative, context);
```

Names/signatures above are **design sketches**, not callable functions.
The C23 descriptor shall document row-major weight layout, offsets,
activation callback lifetime, workspace sizing, non-overlap/aliasing,
finite-domain errors, numeric tolerance, field-evaluation cost, and
transactional commit behavior. No allocation is implicit inside a step.

## 8. Mathematical acceptance gates

1. `roxygen2` documentation gate plus full `devtools::test` / `check` PASS.
2. Pack/unpack exact roundtrip across ≥3 affine layers.
3. `(d,h,1)` forward and gradient equivalence to `vmar_mlp_*`.
4. Multi-hidden-layer analytic gradient verified by finite differences.
5. Deliberately invalid shapes, data and parameters rejected.
6. Same mathematical field evaluated by Euler/RK4, with distinct integrator
   results permitted and field-evaluation budgets declared.
7. R–C23 parity fixtures only after G0.7-A is accepted and C23 layout exists.

**Results at preparation time:** tests and exported references are written,
but R runtime is unavailable in this workspace; no claim of R PASS is made.
