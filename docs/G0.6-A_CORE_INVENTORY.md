# G0.6-A — Verified-core inventory and architectural classification

**Classification date:** 2026-11-22. **Decision status:** normative audit proposal;
the user-reported 17/17 macOS CTest and R–C23 12/12 second-moment parity are
recorded as experimental evidence, not as proof of full DSNeuralRNAS migration.

## 1. Purpose and non-negotiable boundary

vMAR's mission is a coherent C23 computational core for neural learning as an
**observable, explainable and feedback-controlled dynamical system**.

The project is **not** an unbounded catalogue of optimization algorithms,
and verification of an experiment does not automatically promote it to the
stable default core. Euler and RK4 are integration methods; Adam is a
discrete-time reference, not the definition of vMAR learning.

Four evidence classifications are used:

- **CORE-CONTRACTED:** implemented in `vmar_core`, mathematical/software
  contracts and C tests, documented R parity in earlier user validations.
- **CORE-EXPERIMENTAL:** compiled in the installed library but its claimed
  learning benefit/policy is not established. Requires explicit opt-in and
  further review before a stable API.
- **REFERENCE-ONLY:** test/reference files, never linked into `vmar_core`.
- **NOT-MIGRATED:** R source capability or future system extension not yet
  implemented and verified as a C API.

**Do not equate** the first category with a final stable 1.0 API or with
formal verification. Currently the CMake project and API macros state
`0.1.10` and the R package states `0.0.12`.

## 3. What was actually validated

The user supplied: R `vMAR.Core` version `0.0.12` with 351 successful tests,
clean `devtools::check()`, roxygen documentation gate PASS; R–C23 learning,
activation, memory, control, robustness, regime, intervention and transfer
fixtures across preceding milestones; G0.5-E.5.4.3 Adam reference 24/24 parity;
and G0.5-E.5.4.4 second moment 12/12 parity, 17/17 CTest suites.

Second-moment causal ablation on the small tested dataset:

1. M1 and observational M2 produce identical theta/m trajectories.
2. Second moment is finite/observable.
3. **M2C was worse in all 12 paired cases**, so it is not a default core policy.

These are **bounded numerical and behavioral tests**, not global numerical
stability proofs, universal optimization superiority, or formal specification
proofs. A pass on macOS is reported by the researcher; the downloadable
archive does not contain the user's entire generated fixture dataset.

## 4. Reproducibility gaps to resolve at consolidation

1. **Version/report consistency.** The old `README.md` described `0.1.7-alpha`
   while CMake and API headers declare `0.1.10`. Its historical milestone
   sections must not be read as current global validation summaries.
2. **Conditional fixtures.** CMake enables many R–C23 tests only if
   `reference/vmar_*.csv` exists. The complete 17-suite count depends on
   generated files available on the researcher's Mac. Distribution must
   provide a manifest/fixture-generation gate, not silently accept fewer
   checks as equivalent evidence.
3. **R/C implementation equivalence.** Numerical fixture parity covers
   designated cases; it does not establish byte-for-byte or all-input identity.
4. **Cross-project source scope.** The attached archive
   `ProyectosR_FilosfiaDSNeuralRNAS.zip` includes `DSNeuralRNAS`,
   `DSNeuralRNAS.MLP`, `ML.DSNeuralRNAS`, and `ADTR.DSNeuralRNAS`.
   Their existence supports a migration backlog, not completion of the C API.
5. **FormalSpec and partial EQUDIF.** Their detailed current contracts and
   source versions must be audited from their own authoritative repositories
   before assigning individual functions to C. EQUDIF was described as 65%
   complete; no unverified completion claims are allowed.
6. **Reproducibility metadata.** Record compiler flags, toolchain, fixtures,
   absolute/relative tolerances, dataset and package/git revisions.

## 5. Mandatory G0.6-B architecture contracts

- **State contract:** explicit dimension, layout, ownership, finite values,
  legal domain and initialization. Keep generic ODE state independent of
  domain-specific `[theta,m]` and research-only `[theta,m,v]`.
- **Field contract:** one semantics for callback evaluation and cost; avoid
  duplicate hidden gradients in R reference fields when accounting budgets.
- **Memory contract:** distinguish observation from feedback intervention.
- **Integrator contract:** field semantics do not depend on Euler/RK4 choice;
  costs and tolerances are explicit.
- **Activation contract:** built-in and custom/parametric functions return
  value, input derivative and parameter derivatives consistently.
- **Control contract:** atomic accepted/rejected transition, logging and
  diagnostics; do not embed a particular regime policy into the generic step.
- **FormalSpec contract:** each exported operation maps to preconditions,
  invariants, postconditions, numerical exception handling and test IDs.
- **No ABI break without review:** preserve current names and statuses during
  G0.6-B inventory unification; versioned change proposals precede mutations.

## 6. Exit criterion and recommended next milestone

**G0.6-A is documentary/classification-complete** once the matrix and
decisions are accepted. It is **not a declaration that DSNeuralRNAS has been
fully ported**.

**Next: G0.6-B — Unified state/API contracts and migration boundary.** Begin
with the minimal stable mechanisms, explicit extension points and MLP

before porting. Preserve the distinction between R reference validation and
C23 executable equivalence throughout.
