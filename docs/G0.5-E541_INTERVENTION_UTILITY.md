# G0.5-E.5.4.1 — Effective utility of adaptive memory intervention

**Status:** independent scientific audit, pending R and R–C23 execution.
**Core compatibility:** unchanged `vMAR.Core 0.0.12` and `vMAR 0.1.10-alpha`.
No new learning algorithm or public API is introduced.

## Central falsifiable question

Does the adaptive policy actually employ memory to improve the learning
trajectory, or does it merely abstain from coupling (`c=0`) and reproduce
the observational baseline?

For each confirmed pre-step state, record a **non-retroactive** diagnostic
`c_k`, gradient norm `G_k`, memory norm `M_k`, alignment and regime. Define:

```
intervention_rate   = sum(c_k > 1e-14) / N
mean_coupling       = sum(c_k) / N
relative_contribution = sum(c_k*M_k/G_k) / N,
    with zero contribution when G_k <= 1e-12
```

The intervention threshold `1e-14` is an operational reporting convention.
These diagnostics describe actual influence but do **not** prove causality.
There is a fundamental distinction between a policy with no rejections and a
policy delivering superior learning outcomes.

## Experimental strata

Three policies (`observe: c=0`, `fixed: c=0.2`, `adaptive: bounded c_k`) are
evaluated for two integrators (Euler/RK4), two weight perturbations
(`-0.1,+0.1`) and two initial memory values (`-0.8,+0.8`). All use the
same three-sample PReLU reference neuron, `eta=0.3`, `tau=0.8`.

### Controlled trajectories (24 cases)

Each trajectory targets `t=1` through up to 160 sequential control
proposals, initially `h=min(0.1,1-time)`, reduction factor `0.5`, four
attempts per proposal and memory threshold `0.5`. Record the **actual**
reached time, accepted/rejected counts and *separate* field and diagnostic
gradient costs. On exhausting retries, the path stops and is labeled
`exhausted` rather than silently assuming it reached `t=1`. A maximum-step
limit is reported as `max_steps`, not successful convergence.

### Equal time and equal diagnostic-aware budget (24 cases)

All policies observe a diagnostic once at each step. Observational and fixed
policies ignore it for control but incur the **same diagnostic cost**. This
provides an explicit, matched total of 40 analytical gradient evaluations:

| Integrator | Steps | Field gradient evaluations | Diagnostic gradients | Total |
| --- | ---: | ---: | ---: | ---: |
| Euler | 20 | 20 | 20 | 40 |
| RK4 | 8 | 32 | 8 | 40 |

The end time is `t=1` for every equal-budget case. This budget excludes
objective evaluations, allocator overhead and runtime, so **equal gradient
evaluation count is not equal execution time**. The policy is frozen during
each integration step, including all RK4 internal stages.

## Source products and parity

From the C project root with the validated R package loaded, execute
`source("reference/run_R_intervention_audit.R")` to generate:

- `reference/e541/controlled_summary.csv` — 24 controlled cases;
- `reference/e541/intervention_trace.csv` — every diagnostic and control
  proposal, including rejected ones;
- `reference/e541/equal_budget.csv` — 24 equal-time/equal-budget cases;
- `reference/vmar_intervention_parity.csv` — numerical fixture for 24
  independent C23 trajectories and intervention metrics.

Reconfigure CMake after generating the fixture, run CTest and execute
`vmar_test_intervention_parity` directly. Numerical parity alone does not
authorize a superiority claim.

## Approval decision

First investigate distributions of intervention rates and coupling intensity,
then compare loss only in equal-time/equal-budget strata. Report whether any
adaptive performance difference persists when adaptive coupling is strictly
positive and whether it generalizes beyond this one dataset and activation.
If `adaptive` is numerically identical to `observe`, record that as an
important **negative** result rather than a success of memory adaptation.
