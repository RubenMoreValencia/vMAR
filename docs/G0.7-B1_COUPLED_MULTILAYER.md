# G0.7-B.1 — Multilayer learning, first memory and feedback control

## Status and scientific claim boundary

G0.7-B was accepted by Rubén on the basis of 22/22 CTest tests, 171 C
assertions and 50/50 R–C23 multilayer parity coordinates on Apple Clang.
This stage adds a **candidate coupled system**, not evidence that coupling
improves learning across datasets. Promotion requires new R–C23 parity.

C library: 0.1.14-alpha. R experimental reference: 0.0.14.

## State and differential equations

An existing `vmar_network_layout` with `p` parameters is retained unchanged.
The new system state has exactly `2p` doubles:

`s = [theta[0..p-1], memory[0..p-1]]`.

With gradient `g(theta) = grad_theta MSE(theta)`:

`dtheta/dt = -eta * (g(theta) + coupling * memory)`

`dmemory/dt = (g(theta) - memory) / tau`.

Inputs: positive finite `eta`, `tau`, nonnegative finite `coupling`.
The memory is a dynamical, first-moment-inspired filter of the gradient.
Its continuous-time semantics are explicitly **not identical to Adam's
discrete bias-corrected first moment**. No second-moment scaling is enabled.

`coupling = 0` restores the G0.7-B theta trajectory under either Euler or
RK4, with memory merely observed. This is a central non-regression property.

## Feedback controller

The controller accepts a candidate only if
`loss(theta_candidate) <= loss(theta_confirmed) + tolerance`.

- An optional gate reduces the initial step when **confirmed pre-step**
  `max(abs(memory))` exceeds `memory_threshold`.
- Failed acceptance retries from the same confirmed state and time, reducing
  the step by the selected ratio.
- Acceptances commit theta, memory, time and identifier together.
- Exhausted proposals preserve state/time/identifier, while reporting
  rejection counts, attempted step and field evaluations.
- Acceptance is a loss-based operational contract, not a universal numerical
  stability theorem or an exact-time guarantee.

The `vmar_network_system_field` callback works with Euler and RK4, using
exactly the same differential equations. Workspace remains caller-owned:
`vmar_network_workspace_required()` for the neural field and
`vmar_network_control_workspace_required()` for controller/integrator stages.
No heap allocation or new training optimizer is introduced.

## Implementation and test gates

- C: `include/vmar/network_system.h`, `src/vmar_network_system.c`.
- R: `vMAR.Core/R/network_system.R` with roxygen2 documentation.
- C contracts: `tests/test_network_system.c` (133 local GCC assertions pass).
- R contracts: `tests/testthat/test-network-system.R`.
- Numerical parity: R generates **320 scalar state-coordinate rows** from
  eight controlled cases: two integrators, two couplings and two proposed
  step scales. C independently recomputes them using
  `tests/test_network_system_parity.c`.

The full R–C23 parity gate has **not yet been executed** in this environment.
The local environment lacks R and CMake; local C syntax and contracts were
checked with GCC `-std=c2x`. Apple Clang/CLion remains the release target.

## Reproduce on Rubén's Mac

After extracting the ZIP, place the updated `vMAR.Core` and `vMAR` projects
in their established locations. In R:

```r
setwd("/Users/rubenmorevalencia/Desktop/SYJ/vMAR.Core")
source("tools/verify_documentation.R")
devtools::test()
devtools::check()
devtools::load_all()

setwd("/Users/rubenmorevalencia/Desktop/vMAR_Proyecto/vMAR")
source("reference/generate_R_multilayer_system_fixtures.R")
source("reference/recover_historical_fixtures.R")
```

The historical recovery script **only generates missing files**, maps
each of the original 14 filenames to its original R generator, and writes
`reference/historical_fixture_recovery.csv` with MD5 checksums and errors.
It does not declare unavailable fixtures to be passing, synthesize values
from C results or replace preexisting fixtures. Some generators may depend
on installed ecosystem packages and their original R versions.

Then, in CLion Terminal (from `vMAR`):

```sh
cmake -S . -B cmake-build-debug -DCMAKE_BUILD_TYPE=Debug
cmake --build cmake-build-debug
ctest --test-dir cmake-build-debug --output-on-failure
./cmake-build-debug/vmar_test_network_system
./cmake-build-debug/vmar_test_network_system_parity \
  reference/vmar_multilayer_system_parity.csv
```

When the historical recovery reports **14/14**, additionally execute:

```sh
cmake -S . -B cmake-build-scientific -DCMAKE_BUILD_TYPE=Debug \
  -DVMAR_STRICT_PARITY_FIXTURES=ON
cmake --build cmake-build-scientific
ctest --test-dir cmake-build-scientific --output-on-failure
```

**Do not count the 14 old fixtures as recovered merely because the default
CTest suite passes:** absent optional tests are not executed. The new
coupled-MLP parity is its own additional gate.

## Limits and subsequent decision

Initial scope deliberately excludes second-moment control, adaptive
activation parameters, multi-output networks and an automated XAI policy.
The next decision will use observed parity, accepted/rejected interventions,
and equal-budget comparisons to judge whether coupling is worth retaining
as a selectable extension. No superiority law is asserted at this stage.
