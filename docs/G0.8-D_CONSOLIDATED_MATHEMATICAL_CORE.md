# G0.8-D — Consolidation of C01 and mathematical contributions to vMAR

**Rector decision — 2026-11-22:** CLOSE G0.8-C.1 as a **technically
validated experimental implementation** and CLOSE G0.8-D as an
architectural/documentary consolidation. Preserve C01 outside the stable
learning core. The evidence does **not** authorize automatic curvature
feedback, or a claim of generalized predictive value.

`G0.8-D_MATHEMATICAL_MECHANISMS.csv`; it complements but does not overwrite
the G0.7-C mechanism freeze.

## 2. Consolidated mechanism policy

| Layer | Mechanisms | Normative role |
|---|---|---|
| Stable learning | M0, **M1 default** | Differential gradient flow and independently observable first memory |
| Experimental interventions | M2, M3 | Fixed memory coupling or backtracked feedback only when selected |
| Numerical references | Euler, RK4, Adam | Integration and optimizer comparisons; no interchange of learning semantics |
| Experimental observers | **C01** | Local curvature of smooth scalar loss; no state changes |
| Formal observability | DSNeuralRNAS.FormalSpec | Authoritative trace and Ψ/Γ/Φ obligations remain delegated |
| Future candidates | C03 EQUDIF residual memory | Not validated in C23; no admission in G0.8-D |

**C01 does not alter `theta`, time, memory, eta, selected integrator,
accepted/rejected proposals or the canonical augmented state layout.**
It is an explicit function call through a separate optional library,
not part of the installed stable `vmar_core` target and not a default
function of an ordinary training step.

## 3. Mathematical contribution and limits

The G0.8-B.1 three-checkpoint R study found loss and gradient norms
decreasing while the Hessian retained positive and negative eigenvalues.
This **indefinite curvature** is information beyond the two scalar
first-order summaries. Since gradients at those checkpoints were nonzero,
it does **not** identify a stationary saddle point. It does not prove
global stability or imply that Hessian-driven interventions would improve
training.

C23 currently implements the **symmetric Hessian matrix only**. It does
not export a symmetric-eigenvalue classifier. Therefore an observation
record may describe the local matrix but must not claim a C23 curvature
label without a separately tested eigenvalue analysis implementation.

The source-equivalent Hessian uses `2p(p+1)` scalar-loss evaluations,
`p²+p` caller-owned workspace doubles and a hard initial cap of 16
parameters. A complete derivative-based alternative requires a different
contract and cost model. The `symmetry_error=0` field reflects mirrored
construction, not a numerical accuracy certificate.

The following **evidence manifest schema** is a documentation contract;
it is not claimed as an implemented FormalSpec adapter:

| Field | Contract |
|---|---|
| `schema_id` | `VMAR-CURVATURE-EVIDENCE/0.1` |
| `model_version` / `source_hash` | Immutable model and implementation provenance |
| `confirmed_state_id` / `time` | A confirmed pre-existing point on the trajectory, never a rejected proposal |
| `parameter_count` / `theta_layout` | Canonical network parameter count and row-major weights/biases ordering |
| `loss_definition` / `activation_domain` | MSE and smoothness assumptions, not a universal Hessian claim |
| `difference_step` / `method` | Positive finite `h`; `loss_central_4corner_symmetrized` |
| `loss_calls` / `budget_limit` | Actual counted calls and declared budget |
| `numeric_status` | Valid matrix, or explicit failure/unknown; no implicit stability verdict |
| `evidence_origin` | R fixture scenario, C23 test name and version identifiers |

FormalSpec Ψ/Γ/Φ and confirmed-regime proofs **remain delegated**.
The manifest must never be described as a replacement for their functions.

## 6. Final decision and next step

**G0.8-D closes the C01 mathematical scaling cycle.** C01 remains a
scientifically motivated, technically verified **experimental opt-in
observer**. Further research may study larger networks, Hessian-vector
products or eigensolvers only when a specific scientific use justifies
their cost; none is an automatic next hito.

**Recommended next administrative/architectural step:** archive the
G0.8-D register with the validated fixture hashes and exact macOS build
revision, and then return to the rector matrix to consider **at most one
new contribution** when its distinct mathematical need is justified.
The stable default remains M1 and no new control law is introduced.
