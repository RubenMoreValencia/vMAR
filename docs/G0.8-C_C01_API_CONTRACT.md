# G0.8-C — Normative proposed contract for optional C23 curvature

**Maturity:** proposed API specification, **not implemented**. Stable
vMAR API 0.1.16 is unchanged. Names and types below are subject to
review during G0.8-C.1; this document defines acceptance semantics.

## 1. Purpose and mathematical object

At a *confirmed*, caller-selected parameter vector `theta` with `p`
finite coordinates, estimate the local symmetric Hessian of the scalar
loss `L`:

\[
H_{ij} \approx \frac{L(\theta+h e_i+h e_j)
 - L(\theta+h e_i-h e_j)
 - L(\theta-h e_i+h e_j)
 + L(\theta-h e_i-h e_j)}{4h^2}.
\]

Observations must be independently reproducible and must **not** commit
a candidate state, update gradient memory, choose a control action or
change the learning clock. Integrator selection is external.

## 2. Narrow initial interface

The implementation team may adapt spelling but not silently widen
semantics. Suggested conceptual interface:

```c
/* Proposed; not yet a public header. */
typedef vmar_status (*vmar_loss_fn)(const double *theta,
                                   size_t parameters,
                                   void *context, double *out_loss);

typedef struct vmar_curvature_options {
    double step;                 /* positive finite, selected by caller */
    size_t max_parameters;       /* caller limit; 16 suggested default */
    size_t max_loss_calls;       /* explicit evaluation budget */
} vmar_curvature_options;

typedef struct vmar_curvature_report {
    size_t parameters;
    size_t loss_calls;
    double step;
    double symmetry_error;
    /* Numerical-quality flags; no global stability assertion. */
} vmar_curvature_report;

vmar_status vmar_curvature_workspace_required(size_t parameters,
                                             size_t *required_doubles);

vmar_status vmar_curvature_hessian(const double *theta, size_t parameters,
                                  vmar_loss_fn loss, void *context,
                                  const vmar_curvature_options *options,
                                  double *workspace, size_t workspace_doubles,
                                  double *hessian_row_major,
                                  vmar_curvature_report *report);
```

The first release should compute a Hessian and diagnostics of numerical
quality **without embedding a general eigenvalue solver in the main
learning core**. If eigenvalue extrema and curvature class are exported,
they must come from a separately testable symmetric-eigensolver adapter,
with residual/convergence checks and an explicit unknown state on failure.
Merely symmetrizing a computed matrix is not an accuracy certificate.

## 3. Domain and invariants

| Item | Normative requirement |
|---|---|
| Input | `p >= 1`, finite `theta`, finite `step > 0`, valid loss callback, explicit budget, non-overlapping buffers except where specifically documented |
| Parameter cap | Initial opt-in implementation shall reject `p > 16` by default; a larger limit requires explicit resource assessment, not an arbitrary silent increase |
| Cost | With mirrored off-diagonals, nominal `2p(p+1)` callback evaluations; count **actual calls** including failed attempts, and reject before any evaluation if the declared maximum is lower |
| Allocation | Caller-owned workspace; no hidden heap allocation and no static mutable state |
| Output | Dense `p×p` row-major symmetric estimate; report includes numerical step and actual callback count |
| Error | Distinguish invalid arguments, insufficient workspace, non-finite results and callback failure using established `vmar_status` values where possible |
| Transactionality | On validation failure, no output buffers are changed. On callback failure or non-finite intermediate, never return `VMAR_OK` or a valid curvature interpretation; partial diagnostics must be explicitly invalidated |
| Pure observation | No writes to input `theta`, loss dataset, learning memory, rate, field state or confirmed trace |
| Non-smooth functions | Do not assert a classical Hessian near activation kinks such as ReLU; return an unsupported/uncertain diagnostic or require smoothness by contract |
| Numerical uncertainty | Record step and sensitivity comparison with a secondary step when available. An exact status flag is not a proof of true Hessian accuracy |
| FormalSpec | Report checkpoint ID/time, source/model version, objective fingerprint, activation, method, perturbation step, numerical units and cost in a separate evidence adapter |

`max_parameters=16` is a conservative **initial engineering proposal**,
not a mathematical threshold. Its adequacy will be verified at C23 build
time and may be made configurable; for `p=16` the formula implies 544
loss calls and 256 stored Hessian coefficients.

## 4. Scientific interpretation contract

The returned matrix can support future eigen-analysis, but class labels
must not confuse three different claims:

- `indefinite_curvature`: positive and negative eigenvalues above a
  declared tolerance; *does not imply a stationary saddle point*.
- `positive_curvature` / `negative_curvature`: local second-order shape,
  **not** global stability or monotone learning.
- `uncertain`: near-zero eigenvalues, kink/non-smooth objective, solver
  non-convergence, or insufficient precision.

No class label is automatically a request for a different learning
integrator, memory update or control rate.

## 5. Acceptance suite for G0.8-C.1

1. Exact quadratic Hessians: positive, negative, indefinite and singular;
   compare with R at predefined tolerance and `h`.
2. The `tanh` network from G0.8-B.1, checking matrix entries and
   independently verifying eigenvalue extrema if implemented.
3. Deliberate `step` sensitivity: `1e-3`, `1e-4` and a too-small step;
   no claim of numerical accuracy from a label alone.
4. Negative tests: null callback, NaN/Inf state or result, step zero,
   overflowing `p×p` size, insufficient workspace, exhausted budget,
   callback failure and illegal buffer overlap.
5. Mutation test: confirmed `theta`, memory and controller configuration
   identical before and after every diagnostic, including on error.
6. Cost accounting: exactly `2p(p+1)` loss calls on success for the
   proposed full Hessian formula; explicitly reject smaller budgets.
7. Finite, symmetric, row-major Hessian with no hidden use of global
   random seeds or mutable configurations.
8. FormalSpec trace adapter: observation attached to one confirmed state,
   source/step/cost metadata validated, rejected proposals excluded; do
   not reimplement Ψ/Γ/Φ.
9. Preserve G0.7-C M0/M1 stable semantics, M2/M3 opt-in and full strict
   CTest/R parity fixture regressions.

## 6. Documentation and versioning gate

- C header contract in **English**, including units, buffer ownership,
  failure/alias rules, complexity and interpretation limits.
- R documentation if a new R-facing wrapper is added: roxygen2,
  `testthat`, `R CMD check`, with no unresolved documentation links.
- C23: Apple Clang 17, CMake/CTest, include explicit linkage tests;
  do not bump the stable API merely for an unapproved experimental API.
- A separate FormalSpec provenance manifest shall include the reference
  version and tested scenario identifiers.

**Promotion gate:** optional experimental capability only, until the
complete suite passes. Scientific improvement over a baseline optimizer
is neither claimed nor required for an observational diagnostic.
