# G0.7-C — Consolidated multilayer learning core and mechanism selection

**Decision status:** G0.7-B.2 closed by the researcher. This stage selects
an explicit core baseline without enlarging the mathematical search space.
Historical result: vMAR.Core 0.0.15 had 444 passing R assertions, no
`R CMD check` diagnostics; strict Apple Clang/C23 build passed 39/39 tests;
the 32-case fixed-horizon R–C23 study had zero mismatches.

**Consolidation candidate:** vMAR C23 0.1.16-alpha and vMAR.Core 0.0.16.
New consolidated API/parity on macOS is a separate acceptance gate.

## Selection matrix

The authoritative classification is `G0.7-C_MECHANISM_SELECTION.csv`.

| Mode | Position | State behavior | Learning and decision |
| --- | --- | --- | --- |
| M0 | stable reference | theta evolves; memory frozen | baseline gradient flow |
| M1 | **stable default** | theta and memory evolve | memory observes, cannot influence theta |
| M2 | experimental opt-in | theta and memory evolve | fixed memory coupling |
| M3 | experimental opt-in | theta and memory evolve | coupling with loss-gated backtracking |

These modes share one canonical caller-owned `2*p` state layout. `M0`
does **not** evolve or erase the memory block; it keeps it frozen for exact
baseline reproducibility. `M1` evolves memory but guarantees zero effect
on theta. `M2` and `M3` reuse the audited coupled system of G0.7-B.1.

The programmatic default is M1. No global mutable mode registry or implicit
heuristic chooses a research policy without explicit user selection.

## Architecture and explainability contract

`include/vmar/network_mechanism.h` exports:

- `vmar_network_default_mode()`;
- `vmar_network_mechanism_step()`;
- `vmar_network_decision` with selected mode, acceptance, attempts,
  rejections, field calls, before/after loss, pre-step gradient and memory
  norms, scale of pre-step memory influence, requested/effective step,
  before/after time.

All diagnostics refer to the **confirmed pre-step state**, except loss
after and time after. In M1/M0, memory influence is reported exactly zero.
In M2/M3, the reported memory contribution norm is
`eta * coupling * ||memory||` in gradient-flow units; this is not the
causal change in loss nor a FormalSpec proof. The report permits, but does
not replace, subsequent differential or paired counterfactual analysis.

Each mode reuses existing functions:

- M0: `vmar_network_field`, no duplicated learning equation.
- M1/M2: `vmar_network_system_field` with coupling fixed at 0 or configured.
- M3: `vmar_network_control_step`, with backtracking and atomic commits.
- All methods: `vmar_step` Euler or RK4; integration is independent of
  the learning/control policy.

FormalSpec Psi/Gamma/Phi remain delegated to the original FormalSpec
implementation. The new decision report is an interoperability candidate,
not a claim that these obligations are formally proven.

## Accepted scientific interpretation of G0.7-B.2

- M0 and M1 have identical final loss and theta trajectories in the tested
  regimes (observable memory is decoupled by construction).
- M2's mean loss improved by approximately 0.66–0.68% relative to M1
  with equal field evaluations and time in the small benchmark.
- M3 consumed 5.4 times more field evaluations and did not clearly improve
  mean loss beyond M2. The extra operations came from the memory step gate;
  no loss-based rejection occurred in that benchmark.
- Across 16 paired contrasts there were 12 positive and four unfavorable
  results. No universal superiority or formal learning law follows.

Therefore M2 and M3 are **available but not automatically activated**.
