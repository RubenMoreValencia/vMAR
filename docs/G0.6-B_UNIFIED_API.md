# G0.6-B — Unified state, contract and API architecture (C23)

**Status:** additive contract implementation, locally compiled and unit-tested;
macOS CLion/CTest validation pending. This hito specifies compatibility and
extension boundaries, **not** a complete MLP port or FormalSpec proof.

## 1. Architectural decision

The engine must maintain four separable responsibilities:

1. **Mathematical model:** define a field `f(t,s)` and analytical gradient
   where applicable. It owns *meaning*, not integration or retry policies.
2. **Integrator:** compute a tentative next state using Euler or RK4, with
   caller-owned memory. It does not decide whether learning is beneficial.
3. **Observer:** compute diagnostic values from confirmed states, never
   automatically change the state or its governing field.
4. **Controller:** accept/reject proposals transactionally; any policy is
   explicit and testable, independent of how the integrator was chosen.

That partition prevents a mathematical field from being conflated with an
optimizer. Differential time and discrete update count remain distinct.

## 2. Canonical state contract and the new API

`include/vmar/state_layout.h` adds a pure structural descriptor:

| Kind | Layout | Validated invariant |
| --- | --- | --- |
| `VMAR_STATE_PARAMETERS` | `[theta(d)]` | `d>0`, all finite |
| `VMAR_STATE_FIRST_MEMORY` | `[theta(d),m(d)]` | finite values, contiguous equal dimensions |
| `VMAR_STATE_SECOND_MOMENT` | `[theta(d),m(d),v(d)]` | finite values; `v_j>=0` |

`vmar_state_layout_make(d,kind,&layout)` reports offsets and total capacity
in doubles. Missing memory offsets equal `total_doubles` and must never be
dereferenced. `vmar_state_layout_validate(&layout,state,len)` checks the
canonical description against a state and rejects illegal dimensions or
non-finite values. Both are pure, allocation-free and do not mutate inputs.

**Important:** allowing a `v` block in an API description does **not** promote
the second-moment differential model or M2C to the stable core. The latter
remains reference-only, following the unfavorable 12/12 controlled contrasts.
The descriptor is generic state infrastructure, not a new neural algorithm.

Compatibility: existing `vmar_step`, neuron, memory, custom activation,
control and regime signatures are unchanged; enum values and structures are
introduced in a **new header**, not inserted into existing ABI layouts.
Linking old client code against the new static library remains supported at
the source/API level. Binary distribution guarantees require a separate ABI
check before a stable release.

## 3. Strict ownership and mutability

- Input dataset, target and custom activation callbacks remain caller-owned.
- Each contiguous state buffer is caller-owned; `theta`, `m`, `v` are disjoint
  logical segments within that buffer, not independently allocated objects.
- Integrator workspaces are caller-owned and sized through documented APIs.
- State validation does not allocate, normalize, copy or alter a state.
- Numeric failure returns a non-OK status. A rejected control proposal does
  not commit the candidate state, time or step ID.
- For every future public function, declare aliasing restrictions,
  dimensional requirements and whether outputs can be partial on failure.

## 4. Contract mapping and promotion policy

| Operation | Preconditions | Postconditions | Oracle |
| --- | --- | --- | --- |
| `vmar_state_layout_make` | `d>0`; valid enum; no size overflow | Canonical contiguous offsets and total length | `vmar_state_layout_contracts` |
| `vmar_state_layout_validate` | Canonical layout, matching buffer length | State is finite; `v` nonnegative when present | `vmar_state_layout_contracts` |
| `vmar_step` | Positive `h`; finite state; adequate workspace | Next state or unmodified target on failure | Existing core and R parity |
| Neural field | Correct theta/model dimension; analytic gradient | Finite gradient flow derivative | Existing neuron and custom tests |
| Memory primitives | Valid tau/decay and state dimensions | Exact/EMA memory transition per contract | Existing memory tests |
| Controller | Defined policy, workspace, confirmed state | Atomic accept/reject, reported costs | Existing controller and transfer tests |
| Regime diagnosis | Confirmed state and explicit threshold | Descriptive diagnostics, no automatic policy promotion | Existing regime tests |

No reported 351 R tests or 17 Mac CTest suites are replaced by this new
layout test; they remain regression gates. After reconfiguration on the Mac,
`vmar_state_layout_contracts` will add one further suite.

## 5. Neural-network extension contract (design, not implementation)

MLPs must be supported as full, extensible neural architectures, not a
minimal one-hidden-layer special case. An eventual **versioned** model
descriptor should define:

- `layers`: arbitrary positive count; `width[0..L]` with positive sizes.
- For each layer `l`, packed weight matrix `W_l` in declared row-major
  order, bias `b_l`, activation kind/spec and parameter block when trainable.
- Shape-safe forward pass and analytic backward/VJP, including derivatives
  with respect to trainable activation parameters.
- A *flattened theta vector* whose stable layout is part of the model
  descriptor; `m` and optional observation-only `v` have exactly the same
  parameter dimension as theta.
- Explicit initialization strategy and random seed when randomized;
  deterministic fixtures for parity; no hidden global RNG.
- Dataset column/row layout and loss reduction (`MSE` mean over samples)
  with normalization explicitly stated.
- Test gates: single-neuron degeneration identity, finite-difference
  gradient validation, multi-layer R↔C23 parity, shape/overflow checks,
  reentrant callbacks, deterministic state replay.

Do **not** introduce a public `vmar_mlp_*` C signature before auditing the
source functions `rnas_init_mlp`, `rnas_mlp_forward`, `rnas_mlp_backward`,
`rnas_train_mlp`, `rnas_update_params_mlp`, `rnas_predict_mlp` in the original
R repository and reconciling them with `vMAR.Core/R/mlp.R`. An optional
activation protocol must not reimplement common forward/backward logic.

## 6. Documentation, scientific interpretation and cost contracts

- Technical API documentation is in English; scientific discussions may
  occur in Spanish. R package exports require roxygen2, NAMESPACE, testthat,
  and zero-error/zero-warning/zero-note `R CMD check`.
- Count gradient evaluations explicitly. RK4 needs four field evaluations
  per accepted step, Euler one; diagnostic gradients, attempted/rejected
  proposals and final loss probes must be listed separately.
- Loss comparison is defensible only when dataset, model, initial theta,
  time horizon or training budget, and tuning policy are aligned.
- Traceability ID for each operation should connect original R method,
  mathematical equation, state pre/post-conditions, C symbol, parity fixture,
  tests and evidence/limitations.
- EQUDIF.DSNeuralRNAS (partially developed) and DSNeuralRNAS.FormalSpec are
  audit inputs, not imported wholesale or declared completed.
