# G0.6-C.2 — Contrato formal de trazabilidad e interoperabilidad

**Status:** C23 recording component implemented with executable structural
tests; R FormalSpec bridge prepared but **not yet executed in the researcher's
macOS environment**. This is a contract, not a mechanized proof of all
learning trajectories or an equivalence claim for Ψ/Γ/Φ.

## 1. Ownership and mathematical semantics

The **confirmed trajectory** is an ordered sequence of states
`S_k=(k,t_k,theta_k,L_k,h_k)`. Here:

- `k` is the integer index of **accepted** updates only: `0,1,...,N`;
- `t_k` is the differential time at the accepted state, not an iteration count;
- `theta_k` may be the complete augmented state, not just a model's trainable
  parameters, when the recorded `dimension` includes memory blocks;
- `L_k` is a finite loss evaluated at the confirmed state;
- `h_0=0`; for `k>0`, `h_k=t_k-t_(k-1)>0`.

**FormalSpec `iter` maps to `k`, not to `t_k`, `attempt_id` or field calls.**
When RK4 is used, the same accepted-index contract holds, but the integrator
requires more field evaluations per proposal. In particular, `h_k` must not be
misrepresented as the optimizer's learning rate `eta_k` when these differ.

The separate attempt log is the ordered sequence
`A_j=(attempt_id,base_iter,accepted,proposed_step,candidate_loss)`.
Rejected attempts never generate confirmed states. The sample R bridge
demonstrates a rejected proposal with a nonfinite loss represented as `NA`,
kept out of the scientific trace. **The attempt log is not FormalSpec Ψ/Γ/Φ.**

## 2. Executable C23 contracts

| ID | Function | Preconditions | Postcondition / invariant | Failure behavior |
| --- | --- | --- | --- | --- |
| `TR-C01` | `vmar_trace_init` | Positive dimension/capacity; non-null owned arrays; capacity multiplication fits | Empty trace referencing caller buffers | No mutation on invalid input |
| `TR-C02` | `vmar_trace_append` | Capacity available; finite state/time/loss/step; initial `(iter=0,step=0)` or next strictly increasing time with `iter=prev+1` and `step≈Δt` | Copies snapshot once and increments length once | Failed append does not commit a record or alter length |
| `TR-C03` | `vmar_attempt_log_init` | Non-null log and array; positive capacity | Separate empty log | No mutation on invalid input |
| `TR-C04` | `vmar_attempt_log_append` | Sequential attempt IDs starting at 0, positive proposed step, accepted boolean; accepted candidate loss finite | Appends one attempt, never touches confirmed trace | Failed append does not change log length |
| `TR-R01` | `vmar_as_formalspec_trace` | Confirmed frame with `iter,time,loss,step,theta*`; explicit `dsfs_metadata`; FormalSpec 1.0.0 | Validated `dsfs_trace`, attempt log kept separate, step schedule retained outside FormalSpec | Fail closed on gaps, time mismatch, missing data or corrupted attempt log |
| `TR-R02` | Scientific reference comparison | Quadratic `diag(1,4)` with frozen schedule | 19 states, identical theta/loss to `dsfs_quadratic_trace` within declared tolerance | Error; no automatic parameter recalibration |

Only `vmar_trace_*` and `vmar_attempt_log_*` are added to C23's installable
core. They **record** data; they do not implement FormalSpec semantics or
allocate memory. The function does not own/lifetime-manage caller buffers.
Controller instrumentation is an explicit call-site responsibility; this
milestone does not silently wire recording into every controller.

## 3. Semantic mapping to FormalSpec

| vMAR data | FormalSpec | Treatment |
| --- | --- | --- |
| `iter` confirmed counter | `iter` | Identity; strict increase |
| `loss` confirmed loss | `loss` | Identity; finite |
| `theta1..thetaD` | Optional numeric trace columns / theta input to observable derivation | Retain when supplied; explicit dimension |
| `time` | Additional trace column | Retain for physical/differential interpretation; not automatically window axis |
| `step` | No identical reserved meaning | Store separately as integration steps |
| `eta` if explicitly supplied | `eta` | Only optimizer learning rate, never inferred from RK4 step |
| `accepted/rejected`, retries | No state equivalent | Preserve as separate attempt evidence |
| Provenance: engine/version/seed/dataset/model/optimizer | `dsfs_metadata` | Required explicit nonempty fields; `NA` seed only if deterministic |

FormalSpec itself validates `iter`, `loss`, metadata and version. Additional
R adapter preconditions align the exported data to the more restrictive
vMAR C trace contract. The adapter does **not** sort, deduplicate, interpolate,
or silently repair input.

## 5. Restricted scope and promotion rule

- Ψ, Γ, Φ stay in `DSNeuralRNAS.FormalSpec` under version 1.0.0.
- No new integrators, activation functions or optimization mechanisms.
- No mixing attempts with accepted states; no reindexing to hide rejection.
- `param_norm`, `grad_norm` and derived observables may be evaluated by
  FormalSpec using explicit theta/gradient inputs; no manufactured values.
- New C23 analytical observers require a separately documented equivalence
  fixture, mathematical contract and evidence of use.

**Research significance:** this creates an auditable boundary from
`evolution -> trace -> independent semantic analysis` while preserving
the distinction between numeric computation and explainable interpretation.
