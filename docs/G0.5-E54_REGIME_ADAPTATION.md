# G0.5-E.5.4 — Dynamic regimes and falsifiable adaptive coupling

**Status:** experimental specification and implementation, awaiting R check
and R–C23 parity validation. This is **not** a general convergence theorem.

## 1. Observable diagnostics

For the confirmed augmented state `S=[theta,m]` calculate the current neural
gradient `g=gradient L(theta)`. Define:

```
G = ||g||_2,    M = ||m||_2
alignment = dot(g,m)/(G*M), if G and M exceed epsilon; else 0
risk_ratio = c_max * M/G, if G > epsilon; else 0 (diagnostic convention)
```

`epsilon=1e-12` is a numerical convention, not a stability threshold. The
reported regimes are `stationary` (G small), `unobserved` (M small),
`aligned` (cosine positive), `opposed` (cosine negative), and `orthogonal`.
These are geometric diagnostics, **not** validated Lyapunov regimes.

## 2. Bounded candidate policy

For `c_max>=0`, propose the following hypothesis-driven coupling:

```
if G <= epsilon or M <= epsilon or alignment <= 0:
    c = 0
else:
    c = c_max * alignment * min(1, G/M)
```

This yields `0<=c<=c_max`. In an aligned regime, the coupling contribution
satisfies `||c*m|| <= c_max * ||g||`, limiting its magnitude relative to the
gradient; when opposed, the proposal returns to observational memory. These
properties do not establish stability or improved optimization. If the
gradient norm is almost zero, the policy abstains from coupling.

The policy is evaluated **once per confirmed control step** and frozen for
every RK4 stage and retry. It is recalculated only from a subsequent
confirmed state; rejected transactions do not advance its memory.

## 3. Comparison protocol

`reference/run_R_regime_study.R` creates:

- 32 diagnostic/one-step R–C23 parity cases across integrator, c_max,
  first-weight perturbation, initial memory sign, and initial step.
- 96 controlled trajectories across policies `observe (c=0)`,
  `fixed (c=c_max)`, and `adaptive (bounded diagnostic)` for the same
  confirmed initial conditions.

Metrics include accepted transitions, rejected attempts, field evaluations,
final reached time, loss and initial loss. A lower raw loss at earlier time
is **not** evidence of superiority. Before any comparative conclusion,
stratify by reached time, apply equal-time/equal-budget protocols and test
across new datasets and activations. All test results are descriptive.

## 4. Validation gates

1. From the R package directory run
   `source("tools/verify_documentation.R")`, `devtools::test()`,
   `devtools::check()` and `devtools::load_all()`.
2. From C project root run `source("reference/run_R_regime_study.R")`
   to generate `reference/vmar_regime_parity.csv` (32 cases) and
   `reference/e54/policy_comparison.csv` (96 cases).
3. Reconfigure/build CMake; run all CTest suites and
   `vmar_test_regime_parity reference/vmar_regime_parity.csv`.
4. Record disagreements, rejected cases and numerical tolerances before
   authorizing any expansion of the core policy.

### Limitations

Only PReLU, a small fixed dataset and a limited parameter grid are covered.
The coupling heuristic is a falsifiable candidate motivated by gradient-memory
geometry, **not** Adam, a guarantee of stable differential evolution, or a
theory of optimal feedback. A subsequent audit should include smooth and
nonsmooth activations, noisy gradients and independent trajectories.
