# G0.5-E.5.4.3 — Adam correspondence and bounded reference audit

Status: **implemented as a research protocol; cross-language experimental parity pending execution on the user's Mac**.

## Mathematical distinction

The current vMAR state `(theta, memory)` has first-order differential memory,
`dm/dt=(g(theta)-m)/tau`. For a **constant input gradient**, the exact update
over a step `h` is `m_next=beta*m+(1-beta)*g`, with `beta=exp(-h/tau)`.
This reproduces the **uncorrected first Adam moment** for corresponding `beta1`,
but not the Adam optimizer, nor its transient bias correction. It also does not
assert equivalence for nonconstant gradients under arbitrary integrators.

An additional candidate state `v` could obey
`dv/dt=(g(theta)^2-v)/tau2` componentwise. Its frozen-input exact update
reproduces Adam's **uncorrected second moment** with `beta2=exp(-h/tau2)`.
This equation is a **candidate for later evaluation**, not part of vMAR-Core.

Adam further requires corrected moments
`mhat=m/(1-beta1^k)` and `vhat=v/(1-beta2^k)` and the discrete update
`theta_next=theta-lr*mhat/(sqrt(vhat)+epsilon)`.
These are algorithm-specific operations; they do **not** follow automatically
from the present vMAR coupled differential learning law. In particular:

- Parameterwise preconditioning changes the vector field's geometry.
- Initial-bias correction depends on the update counter and zero initialization.
- Coupled vMAR feedback is a distinct intervention, not Adam momentum.
- A second-moment controller needs positivity, finite-value and scaling contracts.

## Bounded experimental protocol

| Contract | Adam research comparator | vMAR reference |
| --- | --- | --- |
| Dataset / loss | Same 3-sample full-batch MSE and analytic gradient | Same |
| Models | `tanh`, trainable `prelu`, trainable `swish` | Same |
| Initial theta | `(0.2+perturb, -0.4, 0.15[, alpha])`, `perturb = +-0.1` | Same |
| Initial optimizer memory | `m0 = v0 = 0`, never copied from vMAR | vMAR memory initial value is separately identified |
| Budget | 40 **training** gradient calls; 40 discrete updates | 40 field/diagnostic gradient calls in E.5.4.2 |
| Hyperparameters | `lr = {0.001,0.01}`, `beta1 = {0.8,0.9}`, `beta2=0.999`, `epsilon=1e-8` | Existing preregistered settings |
| Cases | 3 x 2 x 2 x 2 = **24** | Earlier 72 trajectories; compare only matching conditions |
| Output | Initial/final loss; theta; moments; calls; updates | Initial/final loss; theta; memory; calls; accepted steps |
| Comparison | Shared gradient budget only | Same budget; NOT equal physical/differential time |

**Important accounting:** The loss evaluated to report initial/final quality is
not counted among 40 **training** gradients; both sides must disclose such
diagnostic evaluations. Euler/RK4 may take different numbers of accepted
steps under the same field-evaluation budget. A separate wall-clock benchmark
would be needed for a computational-speed claim.

No test data are used to select a best Adam hyperparameter: the two-by-two
grid is a **sensitivity audit**, not optimization or a performance winner.
Any later tuning must use a separate tuning set and declare its own gradient
budget. The test set and evaluation budget remain untouched.

## Files and commands

From the vMAR C23 project root, after loading the R reference package:

```r
source("reference/run_R_adam_audit.R")
```

This writes `reference/e543/adam_sensitivity.csv` and
`reference/vmar_adam_parity.csv` (24 rows). Then:

```sh
cmake -S . -B cmake-build-debug -DCMAKE_BUILD_TYPE=Debug
cmake --build cmake-build-debug
ctest --test-dir cmake-build-debug --output-on-failure
./cmake-build-debug/vmar_test_adam_parity reference/vmar_adam_parity.csv
```

The C research comparator is in `reference/adam_reference.c`, separately
linked into tests. The installable `vmar_core` and its public ABI remain
unchanged. `vmar_adam_reference_contracts` additionally tests the moment
recurrence, zero initialization, finite-value rejection, atomicity, and the
exact frozen-input relaxation correspondence.

## Scientific acceptance gate

1. All R fixture generation assertions and 24 R-C23 cases pass.
2. 40 training gradients per run; zero optimizer moments; declared hyperparameters.
3. Same dataset and initial theta, including trainable activation coefficients.
4. No claim of equal dynamic time, optimizer identity or generalized superiority.
5. Second-moment differential memory, bias-correction mechanisms and adaptive
   preconditioning remain **candidates** for later controlled ablation.

Passing this audit supports an **external benchmark and a mathematical
correspondence**, not adoption of Adam within the core.
