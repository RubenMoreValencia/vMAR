# G0.5-E.4 — feedback control of confirmed state and memory

## Scientific boundary

This is a deterministic laboratory controller around the **already defined**
augmented neuron field. It does not change the neuron, memory differential
equation or integrator. The acceptance policy is a testable hypothesis, not
proof of global learning convergence or stability.

The confirmed state is `(time, step_id, [theta, memory])`. At an attempted
transition, the controller performs:

1. Evaluate `L(theta_confirmed)`.
2. If `memory_threshold > 0` and the maximum absolute component of confirmed
   memory exceeds it, reduce the *initial* step by `reduction`.
3. From the same confirmed state/time, propose `Euler` or `RK4` on the
   complete augmented differential field.
4. Accept iff `L(theta_candidate) <= L(theta_confirmed) + loss_tolerance`.
5. On acceptance, commit theta, memory, time and step_id together. On
   rejection, preserve all confirmed values, shrink the step and retry.
6. After `max_attempts` unsuccessful proposals, return a normal rejection
   (`VMAR_OK`, `accepted=0`) with unchanged confirmed state.

The policy records old/candidate loss, accepted, attempts, rejected attempts,
effective step, field evaluation count and final confirmed time. It uses the
maximum absolute memory component, **not a norm of the gradient**. The gate
reads only memory from the last confirmed state; candidate memory cannot
retroactively alter its own proposal size.

## Relationship to R vMAR.Core

`vmar_step` in R implements transactional acceptance and observational-memory
commitment. This C controller instead acts on the E.3 continuous *augmented*
state and commits its memory together with the neural state. Thus the two
functions are not asserted to be behaviorally identical. The R parity script
constructs an explicit R reference for precisely the C augmented-state
contract, using the verified R neural loss/gradient and integrators.

## Contracts and limitations

- `vmar_control_workspace_required()` includes one extra candidate-state
  vector beyond the underlying integrator workspace. All workspace and state
  buffers must be disjoint. No heap allocation is performed by the controller.
- The controller uses caller-owned mutable state and writes it only after
  successful acceptance. On normal rejection, time and step_id are unchanged.
- Non-finite and invalid inputs return an error rather than accepting an
  invalid candidate. The first unsupported numeric step is not silently
  retried. A rejected finite step is eligible for backtracking.
- Only a **loss-monotonic** acceptance criterion is provided so far; no
  Lyapunov proof, confidence bound, adaptive optimality or performance claim.
- Controller behavior is tied to a specific loss. Memory can still influence
  the field through `coupling > 0`, independently of the step-size gate.
