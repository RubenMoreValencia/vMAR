# G0.8-C — Admission decision: C01 local curvature diagnostic

**Decision date:** 2026-11-22. **Status:** architecture admitted with
conditions; **no C23 implementation or stable API is claimed** by this
document.

## Decision

**ACCEPT C01 as an explicit, opt-in, non-interventional diagnostic
extension**, initially experimental. Do **not** couple its output to
learning rate, memory, state transitions or M0–M3 policies. An eventual
C23 implementation must pass all tests in `G0.8-C_C01_API_CONTRACT.md`
before any export is considered stable.

The R laboratory functions remain the scientific reference. C23 shall
not duplicate the canonical learning field or modify its existing public
state layout to carry curvature.

## Accepted evidence (reported by the researcher)

| Stage | Evidence | Finding | Limitation |
|---|---|---|---|
| G0.8-B | 4 analytic quadratic cases; 20 step-sensitivity rows | Hessians agree with exact references at declared `h=1e-3`; expected inertia classifications | Synthetic low-dimensional smooth losses |
| G0.8-B | Smooth `tanh` neural objective; cross-method comparison | At `h=1e-3`, loss- and gradient-based Hessians differ by `2.28e-6` | One neural state; two estimators share same analytical objective |
| G0.8-B.1 | 2 integrators × 3 confirmed states × 2 finite-difference steps | Technical gate PASS; method disagreement near `1e-6` at `h=1e-3` and `1e-8` at `h=1e-4` | One 2–2–1 architecture; 9 parameters; no generalization claim |
| G0.8-B.1 | `t=0` to `t=1` RK4 | Loss `0.09568892 → 0.04168714`, gradient norm `0.3061119 → 0.1726684`, eigenvalue extrema `(-0.3142563, 2.685005) → (-0.1744085, 2.629943)` | Euler and RK4 at equal time, **not** equal field-evaluation budget |
| G0.8-B.1 | Evaluation accounting | 180 loss evaluations or 18 full-gradient evaluations per Hessian (`p=9`) | Different computational units; no elapsed-time or memory benchmark |

**Mathematical interpretation.** The Hessian is *indefinite* along the
inspected trajectory while both loss and gradient norm decrease. This
provides second-order geometric information unavailable from those two
scalar summaries alone. It does **not** identify a stationary saddle
point: `||gradient|| > 0` throughout the three checkpoints. The source
classification `saddle` must be translated to
`indefinite_curvature` in explanatory outputs. Neither global stability,
convergence nor a universal benefit of using curvature is established.

## Selection against the alternatives

| Alternative | Verdict | Rationale |
|---|---|---|
| Promote full Hessian into the stable learning system | REJECT | Quadratic memory/cost; no evidence for policy intervention |
| Introduce a default curvature-aware controller | REJECT | No adaptive control experiment establishes utility or safety |
| Keep curvature outside C23 forever | NOT SELECTED | Numerical correspondence and independent explanatory signal justify one bounded opt-in implementation |
| Build optional, budget-limited diagnostics | **SELECTED** | Mathematical interpretability can be offered without changing learning dynamics |

## Release boundaries

1. **C23 experimental only**, new `vmar/curvature.h` separated from
   stable `network.h`, `network_system.h` and controller APIs. Do not
   change the binary layout of existing structs or the M1 default.
2. **No implicit execution.** Diagnostics must require an explicit call;
   users select observation checkpoints and supply the budget.
3. **Fail closed on numerical uncertainty.** No curvature class is
   returned as definitive if eigen-analysis fails or finite differences
   are unreliable. `indefinite_curvature` is not a proof of instability.
4. **FormalSpec boundary.** Publish provenance/observation metadata
   compatible with the existing trace bridge; do not claim C23
   implementations of Ψ/Γ/Φ. Evidence pertains to confirmed states only.
5. **Experimental API promotion** requires correctness on quadratics,
   smooth neural parity with R, budget/aliasing/error contracts, CTest,
   strict historic R–C23 gates and the applicable FormalSpec obligations.

## Approved next implementation step

**G0.8-C.1 — implement the *minimal optional diagnostics module* in C23**,
using the contract in `G0.8-C_C01_API_CONTRACT.md`. The step is authorized
as an **experimental extension**, not as a replacement of R, Euler, RK4,
Adam, or existing vMAR memory and control. Do not start other candidates.

## Stop rule

If Hessian computation cannot respect its declared budget or produce a
reliable numerical status, keep C01 as an R research tool. No implicit
fallback to a cheaper but scientifically inequivalent result is allowed.
