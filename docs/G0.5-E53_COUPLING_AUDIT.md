# G0.5-E.5.3 — Scientific audit of activation, memory and feedback coupling

**Classification:** experimental audit; the validated core API remains frozen.

## Mathematical hypotheses

The joint state is `S=[theta,m]`, with `theta=[weights,bias,alpha]` for a
trainable PReLU slope. The field remains:

```
theta' = -eta * (gradient(theta) + coupling*m)
m'     = (gradient(theta) - m)/tau
```

- **H0:** with `coupling=0`, the theta trajectory does not depend on initial
  memory for identical neural initialization (observational-memory invariant).
- **H1:** positive coupling can change losses and control decisions, without
  pre-assuming the changes are beneficial.
- **H2:** Euler and RK4 can lead to different approximation errors and
  acceptance decisions for the same field.

## Experimental design

Every case uses the same three-observation, two-feature dataset, trainable
PReLU, starting theta `[0.2+perturb,-0.4,0.15,0.1]`, `eta=0.3`, `tau=0.8`.

| Factor | Levels |
| --- | --- |
| Integrator | Euler, RK4 |
| Coupling | `0`, `0.2` |
| First-weight perturbation | `-0.1`, `0`, `0.1` |
| Initial memory | `0`, `0.8` |
| Fixed-time integration step | `0.2`, `0.1` |

### A. Equal final time — 48 cases

Integrate to `t=1` with 5 or 10 steps. Record the final state, loss and
infinity-norm state error against RK4 with `h=0.001` for the same field and
initial condition. The fine RK4 trajectory is a **numerical reference**, not
an analytical exact solution or guaranteed error bound.

### B. Equal field-evaluation budget — 24 cases

Euler performs 40 steps, RK4 10, both to `t=1`, costing 40 field evaluations.
This does not equalize runtime or the cost of other computations.

### C. Feedback-control trajectory — 24 cases

Attempt up to 10 controlled steps with `h=0.1`, backtracking factor `0.5`,
four attempts per proposal, and memory threshold `0.5`. Record accepted
steps, rejections, evaluations, reached time and loss. If a configuration
stops early on rejection, **do not compare its raw loss as equal-time
performance**.

## Acceptance and reproduction

1. With the validated R package loaded, run
   `source("reference/run_R_coupling_audit.R")` from the C project root.
2. Verify 48/24/24 records, fixed final time, equal evaluation budget and
   zero-coupling observational-memory invariance.
3. Reconfigure/build CMake, run CTest; `vmar_r_coupling_parity` independently
   evaluates 48 trajectories and checks R–C23 numerical agreement.
4. Treat improved loss as a *finding in this fixture*, not general evidence
   of convergence, stability or generalization.

PReLU is non-smooth at zero, so RK4's classical smooth-field order cannot
be asserted through such events without additional analysis. Positive
coupling is a research mechanism, not an implementation of Adam.
