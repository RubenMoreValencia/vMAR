# G0.5-E.3 — explicit learning memory and augmented states

## Scope and boundaries

This version separates three mathematical contracts:

1. **Discrete observational EMA**: `m_next = decay*m + (1-decay)*observation`,
   matching `vMAR.Core::vmar_memory_update(kind="ema")` for the value vector.
2. **Exact frozen-signal relaxation**:
   `m_next = m + (1-exp(-h/tau))*(signal-m)`, matching
   `vMAR.Core::vmar_memory_relaxation()`. Its equivalent EMA decay is
   `decay=exp(-h/tau)`. This equivalence holds when the signal is held fixed
   over the step; it is **not** a general equivalence under moving gradients.
3. **Joint learning dynamics** with state `s=[theta,m]`, where each block
   has `features+1` doubles:

```
g = gradient_MSE(theta)
dtheta/dt = -eta * (g + coupling*m)
dm/dt = (g-m)/tau
```

Here memory is explicitly the filtered **gradient observation**. When
`coupling=0`, memory does not change the original neural field, even though
it evolves. `coupling>0` defines an experimental hypothesis and must not be
presented as a validated improvement. `tau` is a positive time scale.

The baseline `vmar_neuron_field` and `vmar_step` remain unchanged. Both
Euler and RK4 integrate the *same six-dimensional* example field; they are
not part of the memory definition. The caller owns the memory, dataset,
state and integrator workspace.

## Known distinctions and limitations

- The R EMA object tracks steps and may store a bounded window; C23 E.3
  implements only the numerical EMA value and relaxation, not window history
  or step metadata. Window/history is deferred until its state and allocation
  policy are specified.
- The augmented dynamic model in R is a **reference formula assembled from
  vMAR.Core neuron functions**, not an already existing monolithic R API.
- Control acceptance/rejection, transaction across memory and parameters,
  adaptive learning rates, normalization, first/second moments and Adam-like
  recursions are **not** implemented here.
- The memory coupling has no independent learning-performance evidence yet.

## Activation expansion gate — deferred

Activation is a *model contract*, not a memory or integrator contract.
Potential candidates: identity/linear, ReLU, leaky-ReLU, softplus, ELU,
GELU and a parametric activation. Each must specify its forward map,
derivative (including nondifferentiable points), parameter range, numerical
stability, original-model compatibility, R-to-C parity, gradient finite
differences, and influence on differential-field regularity. A smooth
activation may simplify continuous dynamics; ReLU-type functions require
explicit piecewise-smooth conventions. No default activation is changed.
