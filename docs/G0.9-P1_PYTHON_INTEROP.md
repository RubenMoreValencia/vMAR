# G0.9-P.1 — Experimental Python–C23 interoperability

**Status:** Local Linux technical gate PASS; Google Colab and public GitHub
revision reproduction PENDING. This is not a general neural-network binding.

## Contract and implementation boundary

- C23 is the sole implementation of the differential integration algorithms.
- `VMAR_BUILD_PYTHON_FFI=ON` builds an optional shared `vmar_ffi` target using
  the same C23 sources as the static library. Default remains OFF.
- The shared target is not installed or exported as part of the supported
  CMake `vmar::core` API. Public headers and installed ABI are unchanged.
- `python/vmar_ctypes.py` binds only `vmar_workspace_required`, `vmar_step`,
  and `vmar_status_string` and implements no numerical integration in Python.
- The Python field callback has the same dimensions and nonfinite constraints
  as C23. Python callback exceptions become `VmarError` after the C call.
- This prototype synchronously calls Python for each field evaluation; it is
  **not** a performance-oriented interface for high-frequency large networks.

## Linux (including Google Colab)

The standalone notebook is at `notebooks/vMAR_G0.9-P1_Colab.ipynb`.
Until this milestone is pushed to GitHub, use the notebook's default
`USE_PUBLIC_GITHUB = False` and upload the matching experimental ZIP. Once
published, change to `True` to clone and report an immutable source SHA.
To reproduce from a repository revision containing this milestone:

```sh
cmake -S . -B build-colab -DCMAKE_BUILD_TYPE=Release \
  -DVMAR_BUILD_TESTS=OFF \
  -DVMAR_BUILD_EXPERIMENTAL_CURVATURE=OFF \
  -DVMAR_BUILD_PYTHON_FFI=ON
cmake --build build-colab --target vmar_ffi
VMAR_FFI_LIBRARY="$PWD/build-colab/libvmar_ffi.so" \
  python3 -m unittest discover -s python -p 'test_interop.py' -v
```

On macOS, the expected dynamic library suffix is `.dylib`, not `.so`.
Windows is not included in this first validated portability gate.

counts, and error handling. Local GCC 14 / Python 3.12 test execution:
