# G0.5-E.5 — versioned activation contracts and R-to-C23 promotion

## Scope and provenance

This milestone **extends R vMAR.Core first** (R package 0.0.9), then
promotes the same mathematical catalog to C23 (vMAR 0.1.7-alpha). The
original DSNeuralRNAS reference only covered `tanh` and `sigmoid` in the
audited one-neuron equivalence. Other activations are **new extensions**,
not historical claims about the original package.

R has a single `vmar_activation_eval(z,activation)` returning `value` and
`derivative`, reused by the R reference neuron and the reference MLP.
The equivalent C23 entry point is `vmar_activation_evaluate()`.

| Name | Activation | Derivative contract |
|---|---|---|
| tanh | `tanh(z)` | `1-tanh(z)^2` |
| sigmoid | `1/(1+exp(-z))` | `sigmoid(z)*(1-sigmoid(z))` |
| identity | `z` | `1` |
| softplus | `max(z,0)+log1p(exp(-abs(z)))` | `sigmoid(z)` |
| relu | `max(z,0)` | `0` for `z<=0`, `1` for `z>0` |
| leaky_relu | `z` if positive, `0.01*z` otherwise | `0.01` at/below zero, `1` above |

The two nonsmooth activations use explicit conventions for their kink:
ReLU derivative 0 at zero, leaky ReLU derivative 0.01 at zero. These
are **computational choices**, not classical derivatives at the kink.
For finite-difference checks, avoid z=0.

R and C use numerically stable sigmoid and softplus expressions for large
finite preactivations. An extreme input may legitimately create a non-finite
loss/gradient due to data scaling; this is a numeric contract error rather
than a claim of learning stability.

## Extensibility versus algorithm collection

The catalog is centrally dispatched rather than reproduced in the neuron
gradient, MLP or integrator. Adding built-in activations requires a named
contract, derivative convention, ABI/version review, tests in both languages
and explicit promotion. It does **not** require modifying the Euler/RK4
implementation or the memory/control equations.

The present C interface is a **versioned built-in catalog**, not yet a
runtime plugin system. User-supplied callbacks/parametric activations,
activation registration, GELU and ELU are deferred to a separately
reviewed ABI extension; they must not be claimed implemented in E.5.

## Tests and acceptance

Local GCC draft-C23:

- 142 activation assertions passed: analytic/numeric derivatives away
  from kinks, forward limits, finite gradients and Euler field identity.
- Existing neuron contracts (58 assertions) and the demanding robustness
  matrix (648 configurations) still pass locally after integration.

The R package includes `test-activation-catalog.R` and should be validated
with `devtools::document()`, `devtools::test()` and `devtools::check()`.
The local execution environment does not provide R; therefore **R check
is pending macOS validation**.

After loading the updated R package, the C root's
`reference/generate_R_activation_fixtures.R` generates 48 cases:
6 activations x 2 integrators x 2 steps x 2 trajectory lengths.
Each record contains initial prediction, loss, analytic gradients, final
parameters and final loss. The C parity comparator uses the established
`5e-11+5e-11*abs(R)` tolerance. Original 16-case neuron parity remains
intact and separate.

## Research gate

Do not infer superior learning or stability solely from final loss or
R–C agreement. Compare matched time horizons, input perturbations,
memory/control policies and field evaluation budgets. Check if nonsmooth
activations change field regularity, dynamic behavior or controller
backtracking. This phase certifies mathematical implementation contracts,
not the full utility of an activation.
